# Cove Resonance V2

> Accepted on 2026-09-28.

这份文档记录 V2 的完整能力、相对上一版公开 main 的变化、真实验收范围、已知边界和后续优化方向。

## V2 相比上一版公开版新增

### Long-wait MCP Listener 正式验收

新增：

```text
cove_bridge_wait
cove_bridge_wait_ack
```

当 Host 对 Widget 的 `ui/message` 有人工确认或前台限制时，可以由用户先明确启动一个模型 turn，让 `cove_bridge_wait` 等待未来事件。

事务链路：

```text
wait
→ event
→ wait_ack
→ 处理 modelContext / visibleText
→ required routed reply（如有）
→ next wait
```

单次等待上限目前为 45 秒。timeout 是正常边界；用户仍明确要求继续监听时，可以继续下一轮 wait。

模型侧 ACK 与 Widget 的 app-only delivered 路径已经分开，两套 Listener 不混用 ACK。

### required reply 闭环

对于网易云聊天室这类必须沿原路回复的事件：

```text
reserve
→ wait 返回
→ ACK
→ cove_bridge_reply
→ next wait
```

如果上一条 required event 还没完成 routed reply，下一次 wait 会返回 `awaitingReply=true`，不会绕过 backpressure。

已 ACK / 已回复的 conversation event 不会在重新监听后重复释放。

### 一起听 authoritative leave

新增：

```text
netease_together_leave
```

退出请求发出后会重新读取 authoritative room status，确认账号已经真正离开房间才返回成功。

如果本来就在房间外，则返回 confirmed no-op，并恢复到等待下一次邀请的状态。

## 已知边界

### Queue 仍是内存态

Bridge 重启后，尚未完成的 pending / reserved event 目前不能 durable recovery。

### Long-wait 不是永久后台任务

它依赖已经存在的模型 turn。V2 验证了多轮 timeout 与数分钟等待，但没有声称所有 Host 都能无限期维持同一个 turn。

### SSE / reconnect 仍值得长期压力测试

极端网络抖动、长时间断线和多 Listener 竞争仍有继续加固空间。

### Together 控制成功不等于媒体版权可播放

房间控制、NIM realtime confirmation 和客户端媒体版权是不同层。V2 不通过 IP spoof 或不必要的媒体 preflight 去掩盖这一边界。

## 下一阶段建议优化

### P0 — SQLite 持久化 Queue

建议优先持久化：

- event payload；
- event lifecycle；
- pending / reserved / delivered；
- reservation owner / timestamp；
- required reply state；
- routed reply dedupe key；
- state stream 最新值；
- retry / release 信息。

目标：Bridge 重启后恢复未完成消息。

### P0 — restart recovery / reservation lease

在 SQLite 基础上继续补：

- reservation TTL；
- worker 崩溃自动 release；
- required reply 恢复；
- delivered / replied terminal state；
- state event compaction；
- conversation event 不丢失、不重复回复。

### P1 — Listener watchdog

- heartbeat；
- reconnect backoff；
- listener health；
- last-success / last-error；
- reconnect count；
- 自动恢复。

### P1 — multi-listener ownership

- consumer identity；
- single-active-listener lock；
- explicit handoff；
- profile-scoped ownership。

### P1 — Observability

## Release discipline

- 不为了测试长期保留临时 worker；
- 不因为媒体地区问题随便加 IP spoof；
- 不把未决定采用的实验功能直接并入正式路径；
- 不对已经工作的 NIM 连接再启动第二套登录；
- 不用 git reset --hard / git clean 解决来源不明的 working tree 问题；
- release 前跑 test、build、diff / secret check；
- 不为了“架构更优雅”重写已经被真实端到端证明过的底层。
